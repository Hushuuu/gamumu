# Magical Athlete：無角色能力的基礎版實作規格

更新日期：2026-10-10。接續 [實作評估](./magical-athlete-implementation-review.md)，本文件定義下一步實作範圍，尚未開始寫遊戲程式。

## 1. 第一版的明確方向

**先做 3–6 人、每人每場一名選手、四場累計得分，所有角色特殊能力關閉。先完成全普通賽道，再加入狂野賽道效果。**

角色名稱、ID、選秀隊伍、一次性派出都保留，角色不會改變骰值、移動距離、得分或回合順序。選秀在此版本主要是選擇外觀；沒有強弱差異，不必展示「保留強角到後場」的策略提示。這個版本以學會操作、驗證競賽流程為目的，遊戲選單與規則應標示「基礎測試版・角色能力關閉」。

## 3. 完整遊戲流程

### 3.1 開始與固定座位

房主選擇基礎版，畫面顯示人數 3–6、四場、角色能力關閉、全普通賽道及獎分。沿用全員在線且 Ready 的開始條件；7 人以上或少於 3 人拒絕開始，不從 12 人房間中暗自挑選參賽者。

開局按當時房間名單保存座位；此後順時針按固定座位處理。固定座位不受累計分數排序影響。伺服器洗 36 張角色牌並擲骰決定選秀起始者，所有結果保存。

起始 roll-off 採最高唯一骰值：例如 `[6,6,4,2]` 由 4 點者開始。若無唯一骰值，例如 `[6,6,3,3]`，全員重擲。這是對原文件平手說明的可執行補完，應列為數位裁定；不讓最高同點者再擲一次來取代此流程。用迭代續行處理重擲，不用無上限遞迴。

### 3.2 兩輪選秀

每輪公開 `2 × 玩家數` 張牌。由起始座位順時針各選一張，再反向各選一張；末位玩家連續選兩次。第二輪起始座位向左移一位，公開全新候選。

四人示例：第一輪 `A B C D D C B A`，第二輪 `B C D A A D C B`。結束後每人 4 張，共用牌堆剩 `36 - 4N` 張；未選用的牌不再參與本局。所有隊伍公開，卡片提示「本版能力關閉」。

只有當前選秀者可操作；每次 30 秒，逾時伺服器從當下合法候選隨機選一張。公開候選不接受前端自行刪除，重複選牌或舊選秀步驟被拒絕。

### 3.3 每場秘密派出

每人從尚未使用的角色選一張並確認，確認後鎖定。公開狀態只顯示各玩家「已選／未選」，本人私密狀態可看到所選卡；不公開他人的本場選擇。全員提交後伺服器一次揭露，角色放在 0。

30 秒到時，從未選玩家的剩餘角色隨機補選；手動提交與逾時使用同一條驗證與推進路徑。第四場雖只剩一張，仍使用相同選角階段並可自動鎖定唯一卡，不要求玩家多按一次；明示系統自動派出。

第一場先手另做一次 roll-off，與選秀先手分開，進入第一場選角前公開。後三場先手按上一場結束時未完賽者中位置最小者；同格候選以同一 roll-off 演算法決定。此平手政策為數位補完。無能力版無淘汰，不需要提前淘汰先手分支。

### 3.4 競賽

每回合只有一個主操作「擲骰前進」。伺服器擲 1–6，`to = min(from + die, finishAt)`。可超過所需步數完賽，不需要剛好擲中。允許多人同格，不絆倒、不決鬥、不觸發角色；骰值沒有加減或重擲。

完成移動後檢查完賽：第一位記冠軍，跳過其後續回合；第二位記亞軍並立即結束該場。只有一名選手在一次操作中移動，因此 V0 不存在同時完賽裁定。

如果尚未結束，轉到下一個未完賽座位，重設 20 秒期限。逾時自動擲骰，斷線同樣處理。伺服器更新後前端播短動畫，使用者不需按「結束回合」，動畫完成也不回報裁決訊息。

### 3.5 場間與整局結果

第二名成立時凍結所有位置，記錄該場冠亞軍及得分、未完賽位置、下一場先手；本場派出的卡全部標記已使用，包含未完賽者。保留場間結果 5 秒，再進下一場選角；第四場直接整局結束。

每場只有冠亞軍得名次，其他玩家只顯示「未完賽」及格位，不把相同格位硬排成第三、第四。四場總分最高的玩家獲勝，並列用 `winnerIds`。結果列每人四場分數及總分，順位相同者並列。

每場分數寫入遊戲帳本；第四場完成後把本局總分加到房間累計，且只入帳一次。不能用房間累計選本局勝者，也不套用其他遊戲的勝者固定 +100 分。

## 4. V1 賽道效果的簡單規格

角色能力持續關閉。這一步只增加地形：

| 類型 | 觸發 | 處理 |
| --- | --- | --- |
| 箭頭 | 一次移動結束停在箭頭格 | 依設定額外前進／後退，保存獨立 `track-move`；落點再檢查效果 |
| 絆倒 | 移動結束停在石頭格 | 記 `tripped=true`；下次本人回合不擲骰，清除狀態並轉下位 |
| 星星 | 一次移動結束停在星星格 | 本局 +1，紀錄來源；下次重新到達可再次得分 |

僅經過效果格不觸發；起始擺放、站著等待與絆倒恢復都不重新觸發停留。後退夾在 0 以上；箭頭導致抵達門檻時可完賽。每段位移先檢查完賽，完賽後不處理不存在的終點地形。從箭頭移動到石頭／星星時要繼續處理該效果。

無能力版恢復回合可以自動完成，並留「恢復站立，本回合跳過」紀錄；不需要按擲骰。冠軍退出競賽回合輪替，其他選手仍可得星星分直到亞軍出現。

積分先用無限整數帳本，不模擬實體銅片耗盡與找零，這是數位版簡化。驗證賽道時拒絕無效箭頭、同格多種效果與必然箭頭循環；由開發者修正資料，不把循環丟給玩家擲骰解決。正式狂野配置若與這些限制不相容，再調整規格。

## 5. 最小狀態與操作契約

### 5.1 狀態機

```text
waiting（房間）
  → draft（兩輪）
  → race-select（共同選角）
  → racing（輪流擲骰）
  → race-results（第 1–3 場，5 秒）
  → race-select（下一場）
  → ... → finished（第 4 場）
```

選秀到場間結果，外層房間狀態皆為 `playing`。V0 不需要 `pre-race`、`pendingChoice`、能力堆疊、複製鏈或循環偵測；V1 地形用小型順序結算函式即可。

| 狀態區 | 最少欄位 |
| --- | --- |
| 版本 | 遊戲 schema、規則版本、能力關閉旗標、賽道與獎分配置快照 |
| 固定玩家 | seat order、player ID、名稱快照、隊伍、已用角色、本局分數 |
| 選秀 | 牌堆、候選、pick order、round、pick index、deadline |
| 選角 | race number、各人私密選擇、已提交玩家、selection ID、deadline |
| 競賽 | 本場選手 ID／owner、position、finished place、V1 tripped、current player、turn ID、deadline |
| 結果 | 四場結果、名次、格位、先手、本局帳本、winner IDs、scores committed、end reason |
| 同步 | state version、最近固定上限 100 筆的序號事件紀錄；四場結果另存不截斷 |

公開投影與私密投影分開產生，不能先傳完整 stored game 再讓前端隱藏。本人私密狀態帶 `raceNumber`／`selectionId`／`stateVersion`，切場清除上一場選擇。

### 5.2 客戶端操作

| Action | Payload | 伺服器必查 |
| --- | --- | --- |
| `draft_pick` | `pickId, racerCardId` | 當前步驟、當前玩家、合法公開卡、期限 |
| `select_racer` | `selectionId, racerCardId` | 本場選角、本人持有、未使用、尚未提交、期限 |
| `roll_main` | `turnId` | 當前玩家、本回合、未完賽、deadline；V1 絆倒者不接受擲骰 |

客戶端不送骰值、最終位置、獎分、先手或能力設定。重複 `turnId` 擲骰、同人多分頁提交、過期 `pickId` 都不得再次更新狀態。

選角按本場 ID 與本人提交狀態驗證，不能因其他玩家提交讓自己失敗。版本用來配對快照，不是所有操作共同的樂觀鎖。逾時先按伺服器 `now` 推進，再拒絕晚到的舊操作。

## 6. 配合現有系統的實作順序

1. 在 `shared/games/magical-athlete.ts` 定義設定、公開／私密 view 與 validator；補 catalog、GameView 聯集、validator registry。公開人數只列 3–6。
2. 新增 Worker 模組的 `types.ts`、`rules.ts`、`engine.ts`、`index.ts`；加入 `StoredGame` 與 registry。沿用 `GameModule`，無需先建立通用能力框架。
3. 以 `start()` 初始化選秀；`handleAction()` 與 `handleAlarm()` 呼叫同一套狀態轉移函式。`nextAlarmAt()` 回傳目前 deadline，使用既有房間保存與計時。
4. `privateState()` 回傳本人尚未揭露的選角，採 `pushPrivateState: true`；`toView()` 只傳公開狀態。重連沿用房間驗證後私密重送。
5. 加入 Setup／Game／Results 三元件與前端 registry、規則 dialog。資產用 `gameAssetUrl()`，先使用既有頭像搭配角色名稱與色塊，不等待插畫完成。
6. 結果頁依遊戲內得分排序；第四場在模組內一次入帳，不增加房間 `finished` 後的新結算 action。
7. 增加 bot 的選秀、秘密選角與擲骰分支，讓完整四場可重複跑；更新遊戲內限制說明。

只保留必要的擴充點：玩家／選手 ID 分開、位移有 `main`／`track` 原因、賽道用資料定義、計分來源可追蹤。角色能力之後可在引擎加時點，現在不預建完整可中斷結算器。

## 7. 手機畫面與線上政策

畫面固定三區：上方顯示場次與當前操作者；中央賽道與棋子；下方只顯示現在能做的一件事。等待者看到「等候某玩家」，不顯示不可用能力按鈕。

- 選秀：候選卡、當前選牌者、每人的公開隊伍；卡面只顯示名字／外觀與能力關閉提示。
- 選角：自己的未用卡、確認按鈕、大家的提交狀態；其他人的選擇揭露前不可見。
- 競賽：格位與位置、剩餘距離、擲骰按鈕、倒數；同格棋子可展開查看姓名。
- 場間／結果：冠亞軍、該場獎分、四場明細；不要求所有人按繼續。

所有骰值與事件紀錄由伺服器決定。動畫可略過、重連可直接切最新位置；擲骰送出後按鈕等待新 turn ID，不靠前端鎖按鈕防重複。

暫時斷線：保留座位、角色與 deadline，逾時照常處理，重連不中斷遊戲。明確退房：整局結束，`endReason: player-left`，本局不入房間分數；遊戲中的座位快照保留結果姓名。房主中止沿用 `abort_game`。這兩者與正常四場結束要有不同結果文案。

基礎設定先固定選秀 30 秒、選角 30 秒、擲骰 20 秒、場間 5 秒，減少設定負擔。房主不需人工裁判、確認分數或推進每場。

## 8. 分階段目標與驗收

| 階段 | 交付內容 | 完成條件 |
| --- | --- | --- |
| A：資料與契約 | V0 固定規則、36 名穩定 ID、view／private validator、註冊與基礎標示 | 3–6 人限制一致；角色能力無法啟用；測試獎分明示；前後端型別通過 |
| B：可運作核心 | 洗牌、roll-off、蛇形選秀、秘密派出、普通移動、四場計分 | 3／4／6 人測試跑完四場，卡數守恆，冠亞軍與並列總勝者正確 |

| 後續另案 | 角色能力、雙選手、更多賽道設定 | 重新確認能力版本與互動裁定，再估工；不是 A–E 的阻擋條件 |

### 必要測試情境

- Roll-off `[6,6,4,2]` 選 4 點、`[6,6,3,3]` 重擲；下一場最落後同格候選再決定先手。
- 四人選秀次序正確；六人共選 24 張，剩餘 12 張；所有卡 ID 無重複。
- 揭露前，其他玩家的 `toView`、事件紀錄都沒有本人的選擇；重連本人看得到自己的鎖定選擇。
- 位置 28 擲 6 完賽；冠軍不再輪到；第二名成立即封存該場，不讓下一名多擲一次。
- 每個角色恰好參賽一次；第 4 場自動派出唯一卡；每場未完賽者卡同樣消耗。
- 正常 V0 的四場獎分總和應為 28，帳本與各玩家總和一致；正常結束重入／alarm 重送不再入帳。
- 逾時與手動操作同時到達只結算一次；DO 保存重新載入後仍用原骰值、原 turn ID、原選牌進度。
- 房間累計領先者不一定是本局勝者；本局同分顯示全部勝者；中止／退房累計分數不變。
