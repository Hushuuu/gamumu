# 阿瓦隆視覺改版規劃：Graphic Flat Design

本規劃以目前的 `AvalonGame.vue`、`AvalonSetup.vue`、`AvalonResults.vue` 與 `AvalonPlayerIdentity.vue` 為改版範圍，目標是讓阿瓦隆更像一款有任務地圖、陣營徽記與階段儀式感的桌遊。

只調整視覺呈現與轉場，不改遊戲規則、伺服器狀態或資訊可見性。現有 `docs/Avalon-plan.md` 保留作規則文件；本規劃獨立列出後續素材需求。

## 1. 視覺方向

**主題：亞瑟王國的桌上任務地圖。** 以圓桌、盾徽、旗幟、城堡、森林與湖泊作為圖像語彙，採用簡潔、明亮、易讀的扁平插畫；避免寫實油畫、金屬 3D、繁複紋理及大量漸層。

| 用途 | 建議色彩 | 呈現方式 |
| --- | --- | --- |
| 共用底色 | 羊皮紙 `#F4F0E4`、暖白 `#FFFDF7` | 大面積留白，局部加簡單地圖線或幾何裝飾 |
| 文字與線稿 | 深墨紫灰 `#302D3D` | 標題、主要輪廓，確保對比清楚 |
| 正義陣營 | 森林綠 `#3E7659`、淺鼠尾草 `#E3F0E7` | 盾牌、桂冠、日光、任務成功 |
| 邪惡陣營 | 莓紅 `#853F4C`、淺玫瑰 `#F5E5E3` | 破裂王冠、暗色旗幟、任務失敗 |
| 王權／重要操作 | 柔金 `#D5AA58` | 王冠、隊長標記、重要邊框；少量點綴 |
| 湖中女神 | 湖水青 `#4A9AA0`、淺水色 `#E1F1F0` | 水波、湖中女神標記與查驗階段 |

阿瓦隆專屬色彩應限於遊戲元件，不更改 `src/style.css` 的全站色票，避免影響其他遊戲。成功／失敗、正義／邪惡都須同時用**文字或圖形**區別，不可只靠綠紅配色。

| --- | --- | --- |

| `AvalonGame.vue` 私人角色卡 | 以陣營色、角色徽記及清楚的資訊區塊建立卡牌感；角色與已知資訊仍是即時文字 | 8 款角色 SVG；全身角色插畫列為後續選配 |

## 3. 素材清單與生成規格

建議集中放在 `public/games/avalon/`，檔名固定、以小寫英文及連字號命名。所有圖檔都**不要包含文字、按鈕、玩家姓名或介面截圖**；這些內容由 Vue 畫面動態呈現。

| ID／優先度 | 素材 | 格式與規格 | 生成內容與搭配用途 |
| --- | --- | --- | --- |
| A01／P0 | 阿瓦隆主徽記 `avalon-crest.svg` | SVG，`viewBox="0 0 128 128"`，透明底、正方構圖 | 以圓桌／盾牌／王冠組成簡潔主徽記；用於遊戲標題、設定區及小型品牌點綴。縮到 24–32px 仍要辨識清楚。 |
| A02／P0 | 角色徽記 8 款，各自一個 SVG | 每個 SVG 同樣為 128×128 viewBox、透明底、相同線條粗細與視覺比例 | 依序製作梅林（星杖／星辰）、派西維爾（盾牌／探察符號）、亞瑟的忠臣（簡潔盾牌）、刺客（短劍）、邪惡爪牙（暗色旗幟）、莫甘娜（月相／面具）、莫德雷德（裂紋王冠）、奧伯倫（獨立面具／月亮）。用於角色卡、設定選項與結算角色名單；不要只用陣營顏色區分。 |
| A03／P1 | 階段圖示 7 款，各自一個 SVG | SVG，正方形透明底；24–32px 顯示仍清晰 | 身分確認（盾牌）、隊長組隊（旗幟）、隊伍投票（選票）、任務（任務旗／劍）、湖中女神（水波／百合）、刺殺（靶心／劍）、結算（桂冠／王冠）。用於目前階段標題與重要提示。 |
| A04／P0 | 任務成功／失敗標記 2 款 | SVG，正方形透明底，可用於約 24px 的任務節點 | 成功以完整旗幟／桂冠表示；失敗以破裂盾牌／倒下旗幟表示。兩個圖形輪廓要明顯不同，且搭配畫面上的「成功／失敗」文字。 |
| A05／P1 | 正義／邪惡陣營徽章 2 款 | SVG，正方形透明底，與角色徽記使用相同線條及色彩規則 | 正義採守護、日光或完整盾牌意象；邪惡採裂紋、暗旗或遮蔽意象。用於陣營標籤、角色卡及結果頁，不能透露尚未公開的玩家角色。 |
| A06／P1 | 正義勝利、邪惡勝利結果插畫 2 張 | WebP，建議 1600×1000 或相近 3:2 比例；桌面與手機裁切時主體都需完整 | 正義版：晨光中的城堡、圓桌或完整旗幟；邪惡版：暮色城堡、破裂旗幟或暗色王冠。兩張構圖、視角、細節密度一致；畫面中央上方留低細節區供 Vue 疊加標題，不能把勝利文字畫進圖內。只用於結算主視覺，不鋪滿進行中的操作畫面。 |
| A07／P2 選配 | 角色立繪 8 張 | WebP，建議 4:5、至少 720×900；同一批次保持相同構圖與光線 | 只有在角色卡要擴大成主要視覺焦點時才製作。每張以單一角色為主體、平面色塊和簡化背景；不要畫角色名稱或規則文字。第一階段先用 A02 角色徽記即可，不必一次製作 8 張立繪。 |

**A02、A03 與 A04 是不同用途的圖組：**角色徽記表示「這是什麼角色」、階段圖示表示「現在進行哪一步」、任務標記表示「任務結果如何」。若希望先控制素材量，A03 可先製作組隊、投票、任務、湖中女神與刺殺五個最常出現的階段圖示。

### 素材共通條件

- SVG 採少量純色、清晰輪廓與一致線寬，不加複雜漸層、模糊陰影或照片紋理。
- 小圖示要在 24px 仍可辨識；插畫需保留手機裁切安全區。
- 角色、任務和結果圖都不能承載必要文字；文字、數字、玩家資訊由介面繪製。
- 同一圖組先固定線稿粗細、邊角形狀、色票與陰影規則，再逐張生成，避免素材風格不一致。

## 4. 動畫規劃

動畫由 Vue 轉場與 CSS `transform`／`opacity` 實作，不把動畫烘焙成 GIF 或影片；素材負責靜態圖形，狀態仍以伺服器回傳為準。

| 觸發時機 | 動畫建議 | 必須遵守 |
| --- | --- | --- |
| 首次進入角色確認 | 角色卡短暫翻面或淡入，約 350–500ms | 不延遲角色資料顯示，不增加會改變原本流程的操作步驟 |
| 選擇隊伍成員／任務目標 | 被選卡片輕微上浮、徽記彈入，約 150–220ms | 清楚保留鍵盤焦點及已選狀態，不使用閃爍 |
| 全員完成隊伍投票後 | 通過／否決徽記短暫蓋章，約 250–350ms | 只在伺服器公布投票結果後播放，不能提早揭露任何人的秘密投票 |
| 任務結果公布 | 成功／失敗標記落在任務路線上，約 300–400ms | 只在整隊出牌完成且結果公開後播放，不顯示個別玩家的秘密任務牌 |
| 湖中女神查驗與交接 | 標記周圍出現一次水波，標記移至新持有人 | 私人查驗結果只由持有人看到；其他玩家的畫面不得以動畫暗示陣營 |
| 刺殺與結算 | 目標卡短暫聚焦，再切換勝負主視覺 | 不呈現血腥畫面、不做強烈閃光，勝負仍以伺服器結果為準 |

所有動畫需提供 `prefers-reduced-motion` 降低動態效果的版本；避免無限循環、持續飄動或影響玩家閱讀的背景動畫。

## 5. 整張圖檔的取捨

- **值得製作：**A06 的兩張結局插畫。結算是靜態、高情緒價值的畫面，最適合用完整場景提升勝負揭曉感。
- **視需求製作：**A07 的角色立繪。它會占用較大版面與素材製作量，先以角色徽記完成第一版，再評估角色卡是否需要更有戲劇性的主視覺。
- **不建議製作：**整張遊戲操作畫面、含文字的任務看板，或鋪滿所有遊戲階段的大型背景圖。玩家名單、任務進度與階段內容會動態改變；手機裁切也容易讓文字失去對比。任務路線以 HTML/CSS 節點搭配 SVG 標記，比一張固定地圖更容易支援不同螢幕。

## 6. 建議製作順序

1. 先確定色票與線稿風格，製作 A01 主徽記作為視覺基準。
2. 依相同規格逐個製作 A02 八款角色徽記及 A04 成功／失敗標記。
3. 製作 A03 階段圖示、A05 陣營徽章，套用到遊戲與設定畫面。
4. 以 CSS 製作選取、投票、任務結果、湖中女神交接等短動畫。
5. 最後製作 A06 兩張結局插畫；確認版面後再決定是否製作 A07 角色立繪。

## 7. 完成視覺改版時的檢查項目

- 320px 寬手機畫面仍能閱讀、操作，任務路線與插畫不會遮住按鈕。
- 正義／邪惡與成功／失敗不只靠顏色，均有文字或圖形線索。
- 投票、任務牌、角色資訊與湖中女神查驗的公開／私人範圍完全不變。
- 動畫只在對應狀態出現一次；減少動態效果設定有效。
- 使用新插畫時，標題、規則說明、玩家名稱等動態內容仍由介面文字顯示。
